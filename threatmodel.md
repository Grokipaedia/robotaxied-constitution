# Threat Model

This document says plainly what the Constitution Firewall protects against, and — more importantly — what it doesn't. A governance layer is only trustworthy if its limits are stated as clearly as its guarantees.

## What this firewall does

Given a proposed action and the actor who proposed it, `evaluate()` and `resolve_conflict()` deterministically decide ALLOW / DENY / ESCALATE against a human-readable, hand-editable policy (`constitution.json`), and `journey_receipt()` produces a hashed, tamper-evident record of every decision made during a trip. Two parties holding the same receipt can independently recompute its SHA-256 hash and confirm the record wasn't altered after the fact.

## What it assumes, and does not verify

- **Actor identity is already authenticated.** The firewall trusts the `actor` field on an `Action` (`"vehicle"`, `"remote_operator"`, `"emergency_authority"`, `"passenger"`). It has no mechanism of its own to verify that a message claiming to be from the remote operator actually came from an authorized remote-operations center, or that a "passenger" request actually came from the person who booked the trip and not someone who gained access to their session. Authentication and message-integrity (e.g., signed commands, mutual TLS between the vehicle and its operator, in-cabin biometric or session binding for passenger requests) is a separate layer this project does not implement and assumes sits underneath it.
- **The vehicle self-reports its own actions honestly.** `journey_receipt()` is only as trustworthy as the log it's built from. If the vehicle's own control computer is compromised and lies about what action it actually took (versus what it reported), the hash proves the *report* wasn't tampered with after logging — it cannot prove the report matched physical reality. Reconciling the receipt against independent telemetry (black-box recorders, roadside infrastructure, other sensors) is outside this project's scope.
- **This is a policy engine, not a safety-critical control system.** It's a reference implementation in plain Python, meant to be read and argued about, not a certified or real-time component. It has no defined behavior under adversarial timing, malformed input beyond basic validation, or resource exhaustion, and it has not been hardened, fuzzed, or reviewed for use in an actual vehicle.
- **`constitution.json` is a policy choice, not a guarantee of correctness.** The firewall enforces whatever hierarchy and rule set are written into the file. A badly-designed policy (e.g., an authority hierarchy that puts the wrong actor on top, or a rule that's more permissive than intended) will be enforced exactly as faithfully as a well-designed one. The firewall's promise is that decisions are *traceable to a specific line in that file* — not that the file itself is correct. Reviewing `constitution.json` is a governance responsibility, not something the code can do for you.
- **No defense against a compromised or malicious remote operator credential.** If an attacker obtains valid remote-operator credentials, every action they take is evaluated as a legitimate remote-operator action — the firewall still denies anything outside `remote_operator_may` (it can't be talked into ignoring a restriction, for instance), but it cannot detect that the credential itself shouldn't be trusted. Credential compromise is a key-management problem, not an authorization-policy problem.
- **Escalation is a signal, not a resolution.** When a conflict ties in the authority hierarchy, the firewall marks it `ESCALATE` and applies neither proposal — but it has no built-in mechanism for what happens next (paging a human, a defined fallback safe state, a timeout). That's left to whatever system wraps this firewall in a real deployment.

## Why state this at all

The core claim of this project — "an instruction should only be acted on when it's authorized, within declared intent, and constitutionally permissible" — is only credible if the boundary of what "authorized" actually checks is explicit. Everything above the line in `constitution.json` and `firewall.py` is enforced deterministically and can be audited line by line. Everything in this document is a boundary this project deliberately doesn't cross, and any real deployment built on top of this reference implementation would need to solve for separately.
